# Product

<!-- impeccable:product-schema 1 -->

## Platform

Native desktop: Herdr 0.1.15 / GPUI JavaScript mod. This is not a web or Android
surface; Impeccable's platform enumeration has no native-desktop value.

## Users

Developers operating local or explicitly selected remote OCQ projects inside
Herdr, beside their existing terminals, Files and Changes.

## Product Purpose

Follow an owned goal from Main through bounded work, independent review and a
retained handoff. Make the next available user action understandable without
reading protocol documentation.

## Capabilities and Constraints

- SQLite is the queue authority; OpenCode owns execution and human permissions.
- The panel displays observed evidence, not inferred agent liveness.
- Unknown execution holds capacity. Never retry uncertain mutations, auto-answer
  requests, infer completion from process exit or grant integration authority.
- Existing exact preview/confirmation and context/epoch/ownership fences remain.
- Native panel collapse must coexist with Files/Changes and retain selection.
- Transport is separate from presentation; push integration is separately owned.
- Main setup is server-local; the panel must not pretend an empty project is a
  working Main or offer a fake one-click setup.

## Confirmed UX Brief

Replace the prose-heavy, awkward UI with compact native task flow, strong
hierarchy, short labels, progressive technical details and useful empty states.
Keep advanced entrypoints and factual safety distinctions.

## Working Assumptions

Task-first project work is the primary landing flow; Queue and Inbox are
secondary. The structured interview was unavailable in this non-interactive
worker. This priority is inferred from the explicit brief, not a separate answer.

## Evidence on Hand

Existing main.js/controllers and docs/herdr.md establish supported actions.
Private installed-frame evidence and UI7 acceptance show real 360px panel
constraints. No sample projects or fabricated job states may ship as real data.

## Product Principles

1. Show the task before the protocol.
2. One clear next action, with evidence available on demand.
3. Never compress an uncertainty into a success claim.
4. Preserve native workspace behavior and explicit human control.
